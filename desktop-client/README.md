# 拾页 · macOS 桌面阅读客户端（0.10.2 预览版）

Tauri 2 + Rust + SQLite，使用 macOS WKWebView 阅读和生成矢量 PDF，不查找或启动外部 Chrome，不需要用户安装 Python、Node、Pandoc 或 TeX。

这是可安装的预览版本，当前安装包面向 **macOS 13+ Apple Silicon（arm64）**。尚未提供 Windows/Linux 发行包，采用本地 ad-hoc 签名，未进行 Apple 开发者证书签名与公证，不能当作已完成公开发行验收的正式版本。

通用网页每次收藏会同时保存两个版本，可在阅读区切换：原貌快照保留来源布局与图标尺寸，并按原始视口缩放；正文剪藏去除导航/侧栏，以适合阅读的排版展示正文、图片和代码。需要搭配扩展1.9.0。HTML/PDF导出使用当前版本，完整JSON和内容库备份保留全部版本。正文识别失败时保留原貌并显示原因。已有快照可获得阅读侧修复，但采集时丢失的样式需要重新收藏。

## 安装与首次连接

1. 打开 [安装包](releases/拾页_0.10.2_arm64.dmg)，把“拾页.app”拖到“Applications”，然后从应用程序打开。
2. 在 Chrome/Edge 等浏览器重新加载 `../exporter-extension/`，确认扩展版本为 **1.9.2**，刷新 ChatGPT 页面。
3. 进入扩展“导出设置 → 拾页客户端”，复制当前扩展 ID。
4. 在客户端“设置 → 浏览器连接”粘贴 ID，点击“连接浏览器”。它会为当前用户已有的 Chrome、Edge、Brave、Chromium、Arc、Opera 配置 Native Messaging Host。各浏览器支持情况仍需实机验收。
5. 回到网页直接选择消息并点击“存到拾页”或导出 PDF。“检查客户端连接”只是诊断按钮，不是使用前置步骤。

扩展重载后会自动检查并重新注入已打开的 ChatGPT 页面，恢复已有消息选择；不自动重发进行中的导出，避免重复生成文件。网页导出会自行握手并通过 Native Messaging 请求启动客户端。首次配对仍需完成一次。

配对必须在应用移动到最终安装位置之后进行；若移动应用或更换扩展 ID，请重新配对。首次安装需要上述一次连接设置，后续设计为按需唤起和复用唯一客户端实例。

网页 PDF 默认选择“拾页客户端”，由客户端在后台生成、浏览器下载。插件未运行客户端时会请求后台启动，不打开阅读窗口或保存对话框。第一次配对仍需手动打开客户端一次。升级时请先完全退出旧版本，再替换应用；原有收藏和配对保留。

客户端“设置 → 通用 → 后台与下载”提供两个设置：

- **轻量模式**（默认开启）：阅读或设置窗口打开时显示 Dock 图标并参与 ⌘Tab 切换；关闭所有应用窗口后仅保留菜单栏图标和后台服务。点击菜单栏“打开拾页”进入内容库，“进入轻量模式”收起阅读和设置窗口，“退出拾页”彻底停止服务。导出引擎按需加载，任务结束后释放隐藏 WebView；不宣称常驻内存为零。
- **网页导出交给浏览器下载**（默认开启）：生成后通过 Native Messaging 分块回传，由浏览器管理下载文件。关闭后恢复客户端选择保存位置的方式。客户端内容库里手动点击导出仍选择保存位置。

插件的 PDF 弹窗另有“同时保存到拾页”，默认勾选并记住选择。取消后只生成 PDF，不新增或更新内容库收藏；浏览器下载和客户端保存位置两种方式均支持。临时网页来源在任务成功、取消或失败后删除，中断任务下次启动时清理；供浏览器下载的 PDF 缓存仍按一天的临时数据规则清理。此功能需要客户端0.3.1及扩展1.4.1，旧客户端会收到明确升级提示，避免误存收藏。

这两个设置独立生效。没有新增 HTTP 监听端口；生成的浏览器 PDF 暂存在 `incoming/`，启动时清理超过一天的临时数据。浏览器是否另弹保存窗口由扩展的“另存为”设置和浏览器下载偏好共同决定。旧版插件不支持分块回传时保持客户端选择位置；请同时升级扩展到1.7.0。

原有 PDF 后端导出入口保留。存到拾页只连接本机客户端，不需要启动旧 Python 服务。暂不支持只靠插件安装桌面应用。

## 通用网页收藏

扩展1.7.0在普通HTTP(S)网页提供独立面板，可保存完整页面静态快照到客户端，或直接下载离线HTML。图片、字体、样式与已捕获的嵌入页面随快照保存；客户端保留原页面布局，嵌入页面静态展开。缺失资源先在插件中确认，不静默当作完整收藏。视频/音频仅保存预览，虚拟列表与未展开内容不保证完整；暂未提供正文提取。客户端阅读与PDF继续使用系统WKWebView，无需外部Chromium。

## 高亮与阅读笔记

收藏阅读区新增“高亮选区”“为选区批注”“标注与笔记”。在正文选中文字后用应用工具栏操作，来源网页仍禁用脚本。面板支持五色高亮、跨段落摘录、段落批注、整页笔记与整理；点击摘录可定位原文，定位失败仍保留文字。原始HTML不因标注而被修改，没有正文编辑器。

侧栏“阅读笔记”打开独立笔记库，集中检索、编辑和导出网页记录，包含仅同步笔记、尚未保存快照的网页。笔记作为独立SQLite记录持久化，全文搜索也能命中批注。浏览器通过显式“同步客户端”双向合并；不是云同步，不依赖Cubox账号。普通来源锚点共享笔记，hash路由分开；同一网址的多个快照共享阅读记录。

“导出笔记”保存带本地时间戳的Markdown；HTML/PDF带高亮和笔记附录，Markdown/TXT附阅读记录，JSON保留结构化数据。客户端备份包含独立笔记表，恢复使用版本与删除记录合并；不复活旧副本中已删除的高亮。网页原有结构大改或重复段落存在歧义时可能无法定位，主文档以外的文字标注暂不支持。

- 持久 SQLite 内容库及离线快照；相同内容去重，选择范围与消息正文保留。
- 三栏界面、隔离原貌阅读、标题目录、中文子串全文检索、收藏夹、标签、备注、星标、已读、阅读进度、可恢复回收站。
- PDF、离线 HTML、Markdown、TXT、完整归档 JSON；内容库备份与恢复。
- 列表多选、当前筛选结果全选、保存时间/标题排序；批量已读、星标、收藏夹、追加标签、移入回收站和恢复。

## 当前边界

- 新应用的原生 UI 自动操作未获工具授权，因此安装后启动、首次配对、真实浏览器冷启动及跨浏览器联动尚未完成端到端实机验收。不能把底层测试通过等同于这些流程已通过。
- 原生 PDF API、分页和高级设置通过独立 WKWebView/PDFKit 检查；完整 Tauri 应用里的导出点击流程仍需验收。
- 原貌收藏暂要求所有所选消息都成功捕获 DOM。未加载消息会停止并提示重试，避免把 Markdown 源码当作原貌保存。
- 完整归档 JSON 支持消息和资源恢复。直接导入 HTML 仅支持其中的内嵌资源；保存页面的 `_files` 相邻目录尚未自动导入。网页独有图表无法在 Markdown/TXT 中原样表达。
- 资源当前仍嵌入快照，尚未实现内容包资源拆分、跨收藏资源去重或压缩；大收藏仍有内存开销。中文搜索使用字面子串，尚无 FTS 分词和搜索命中定位。
- 阅读目录已实现，但图表放大、阅读宽度设置、高亮标注、修订管理和自动更新后续开发。文章采集和云同步暂不包含。
- 当前 Native Messaging 按分块调用连接程序，单块 384 KiB，超大内容的启动开销仍需真实浏览器压测；单条收藏上限 256 MiB。
- 界面关闭和完全退出的实际生命周期行为也列入人工验收，未默认设置开机启动。

## 批量操作

在列表左侧勾选收藏，或勾选“全选当前结果”。跨搜索或筛选保留选择，数量中会提示其他结果里的已选项；“清空选择”清除全部选择。批量追加标签保留已有标签，修改收藏夹需勾选对应开关，留空则移出原收藏夹。回收站仍可恢复。

点击“导出所选”，选择格式和 PDF 设置，再选择一次导出父目录。每次生成独立的 `拾页导出_<时间戳>_<批次标识>` 文件夹，每条收藏各生成一个文件；序号避免同名覆盖。侧栏“批量导出任务”可查看近期任务、所有未完成任务及逐文件错误。单条失败不会阻塞后续文件。取消时立即停止排队文件，当前文件生成结束后取消并删除本任务生成的输出；已有文件不会被覆盖或删除。

## 数据与连接

默认数据：`~/Library/Application Support/io.local.archive-reader/`。

- `library.sqlite3`：管理信息、正文搜索字段。
- `items/<UUID>/archive.json`：结构与消息；`snapshot.html`：内嵌资源的网页原貌。
- `incoming/`：未完成分块和 PDF 临时文件，启动时清理超过一天的遗留临时数据。
- `origins.json`：允许连接的扩展来源；`native-host`：指向当前应用的启动器。
- `reader.sock`：仅当前用户可访问的本机 IPC，应用不监听 TCP 端口。

卸载应用不会主动删除内容目录。回收站使用软删除，没有永久删除入口；完整备份可恢复收藏管理信息。迁移前请从“设置 → 数据与备份”导出备份。当前不做远程同步。

## 构建与检查

开发需要 Rust、Xcode 命令行工具、Node/npm；这些是构建依赖，不是用户使用依赖。

```sh
npm ci
npm run desktop
npm run package:mac
```

`package:mac` 先生成 app，再用无需挂载的磁盘镜像创建方式打包，避免 Finder 布局步骤导致 DMG 卸载占用。

```sh
cargo test --manifest-path src-tauri/Cargo.toml
npm run build
npm run check
npm run check:native-pdf
node scripts/check-advanced-pdf.mjs
node scripts/check-worker.mjs
node scripts/check-bulk.mjs
```

从仓库根目录执行通信检查：

```sh
node desktop-client/scripts/check-extension-transport.mjs
node desktop-client/scripts/check-native-host.mjs
node desktop-client/scripts/check-service.mjs
node desktop-client/scripts/check-batch-service.mjs
node exporter-extension/verify-client-download.mjs
```

UI 检查使用现有 playwright-core 和本机 Chrome，原生 PDF 检查用 Swift 构建独立 WKWebView 探针。它们是开发测试工具，不进入用户客户端的运行依赖。

## 浏览器连接与前台行为（0.8.0 / 插件1.7.0）

“设置 → 浏览器连接”可给每个扩展ID命名，逐个添加、重新配对或移除。多个ID会累积登记到已安装浏览器的Native Messaging配置，同一ID也允许多个会话。每张卡片分别显示注册配置是否有效、最近通信时间、会话在线/断开、插件版本和检测结果。浏览器名称由插件报告，Chrome、Arc等共享UA的浏览器可能显示为Chrome / Chromium，可用自定义名称区分用途。注册成功只表示配置就绪，不代表浏览器在线。

插件在首次显式连接/保存/导出成功后建立独立Native Messaging持续通道，每3秒心跳。点击客户端“检测连接”通过随机挑战进行往返检测；15秒未响应提示超时，心跳超过20秒判为离线。浏览器关闭正常断开及时显示；异常杀死Host依靠超时判断。断线最多重试两次，检测通道不会启动已退出的客户端，浏览器启动/插件重载不会仅为监测而唤起拾页。客户端重启或重试耗尽后，在插件检查连接/保存/导出一次可重新建立通道。旧插件仍能导出，但需升级至1.7.0才能提供实时状态。

实时状态存在于当前运行周期，最近通信时间有单独的本机历史记录。每个持续会话保留一个Native Host进程和扩展后台Worker，不增加客户端渲染窗口。导出仍使用原有独立请求，检测不传输网页正文。

轻量模式仅在没有阅读/设置窗口时采用macOS后台应用策略。打开任一应用窗口会恢复普通应用策略，显示Dock图标并进入⌘Tab应用切换；关闭最后一个应用窗口后回到菜单栏服务。后台PDF窗口不会触发前台策略。

```sh
node scripts/check-connections.mjs
node scripts/check-startup.mjs
node ../exporter-extension/verify-presence.mjs
```

实际隔离进程验证了多个ID/同ID多会话、来源绑定、独立断开、异常Host心跳超时、监测不唤醒及macOS实际ActivationPolicy。Chrome/Edge安装后的完整持续连接及Dock点击/系统切换按键仍需实机验收。

## 设置窗口（0.5.1）

通过应用菜单“设置…”、⌘,、内容库侧栏“设置”或菜单栏图标进入独立设置窗口，集中管理通用、阅读、PDF 导出、浏览器连接、数据与备份和版本信息。重复打开复用同一窗口。关闭设置窗口不停止后台服务。

“通用 → 应用启动时”可选“打开主界面”（默认）或“静默启动”，保存后下次普通冷启动生效。与轻量模式独立：启动方式决定是否显示内容库，轻量模式控制 Dock 和关闭窗口后的行为。插件通过 `--background` 唤起时始终静默，不受启动偏好影响；设置不负责系统登录时自动启动。首次安装默认打开界面以完成配对。

阅读和 PDF 偏好保存后同步到已打开的阅读窗口；PDF 内容标题仍属于单次导出，不设为全局默认。插件自己的 PDF 选项仍由插件独立保存。备份可在设置页导出与恢复。

```sh
npm run check:settings
READER_BROWSER=webkit npm run check:settings
node scripts/check-startup.mjs # 从仓库根目录执行时加 desktop-client/ 前缀
```

## 阅读功能（0.5.0）

打开收藏后默认使用舒适阅读宽度；可切换适配宽度或原始宽度，缩放60%–200%，设置自动保留。专注阅读收起内容库与列表；窄窗口将侧栏改为抽屉，目录可按需展开。目录随阅读位置高亮，底部显示进度并支持返回顶部，重新打开收藏可继续阅读。

“文内查找”（⌘F / Ctrl+F）支持跨行内标签匹配、上一处/下一处及代码命中定位。为控制长文开销，单次搜索最多索引200万字符、展示500处匹配，超过时计数带“+”。当前不包含公式内部的搜索。

“代码”面板可选择代码块、复制完整代码、展开/收起或自动换行；“图片与图表”可逐张查看、适合窗口、原始尺寸与放大。WebKit 对禁用脚本的归档框架限制事件回调，因此 macOS 的操作入口放在应用工具栏，归档继续保持脚本隔离。

所有阅读处理仅作用于临时视图，不改收藏原文。PDF、HTML及其他格式继续从原始收藏导出，不带阅读按钮、折叠限制或查找标记。暂不支持编辑正文。

```sh
npm run check:reading
READER_BROWSER=webkit npm run check:reading
```

检查使用开发环境里的 Playwright Chromium/WebKit，原生命令为模拟；macOS 菜单快捷键和系统剪贴板仍需安装后人工验收。

## 阅读性能修复（0.10.1）

阅读文档共用状态观察器，Chrome使用事件，WKWebView保留只比较滚动位置和选区端点的轻量兼容检测；同一选区不再反复扫描全文。窗口失焦/隐藏时暂停兼容检测，恢复后继续。快照CSS/SVG动画保持静止；原文件不被改写。

切换原貌/正文复用当前收藏的已清理HTML，避免重复DOMPurify解析；阅读布局改为先测量后批量写入，目录位置按布局变化更新，滚动时二分查找。选择收藏不重建整个列表，检索输入真正防抖；档案文件与SQLite命令移至后台线程，原生窗口/剪贴板留在AppKit线程。

隔离浏览器夹具验证约3600节点下同一选区重复索引从3秒12次降至0；Chromium空闲主线程工作显著减少。WebKit的后台可见性暂停使用合成visibilitychange验证，原生焦点另接Tauri窗口事件。以上不是Mac硬件功耗/温度实测，不承诺具体降温或续航比例。

## 大收藏切换（0.10.2）

新增最多3条、估算192MiB字符串预算的近期归档缓存，阅读资源缓存最多4份、目标64MiB；单个超过预算的当前文档保留，离开并淘汰后释放。快速点击合并同条读取，跳过已失效的排队请求。收藏元数据与阅读记录仍重新读取，手动刷新清空缓存。

原生归档通过字节响应传递，减少大HTML在JS回调中的转义；阅读时将大内嵌图片转换为本机Blob资源，避免反复解析几十MB的Base64属性。清理前使用不可猜测的data占位符，清理后只替换本次创建的图片URL；脚本/联网权限保持关闭。资源引用计数、取消与缓存淘汰均释放URL。原始快照、备份和PDF/HTML导出继续使用完整原文件。

本地约40MB收藏在隔离WebKit中，重复打开约1.9秒降至约0.2秒；首次读取仍需读取/解码图片。测量包含真实快照，但原生命令为夹具传递；不等价于已测得用户原生应用中5～10秒延迟的全部来源。
