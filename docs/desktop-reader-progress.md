# 桌面客户端第一阶段进展

2026-11-05：已新增 `desktop-client/`，暂名“拾页”，版本 0.1.0；扩展 1.2.0 增加“存到拾页”。原商业副本 `local-extension/` 没有修改。

## 本阶段结论

- Tauri macOS arm64 应用及 DMG 已实际构建。安装体积明显小于把外部浏览器、Python 与 TeX 整套打包的方案；最终尺寸以交付包为准。
- Native Messaging 与私有 Unix Socket 的启动/接收路径已实现，首次配对在图形界面完成。实际浏览器冷启动尚未验收。
- SQLite 内容与管理状态、归档 JSON/HTML、离线阅读、目录与基本整理已实现。
- 独立 WKWebView 的 AppKit 打印探针产生空白页，因此没有继续使用此打印路径。
- 当前改用 WKWebView `createPDF` 分段矢量输出和 CoreGraphics 合成 A4。不能仅把整张长 PDF 裁成多页：测试发现这会把不可见正文带入每页文字提取结果；分区域调用 WebView 导出避免了该问题。
- 安全分页位置在阅读引擎中的临时文档计算，保护图表和文本行，输出仍是矢量文字。

## 已执行的检查

- Rust 内容库检查：持久保存、内容去重、中文查询、标签与阅读状态、完整快照恢复、非法 ID、分块错序/校验/重复提交。
- 扩展 Core 与 Background 联合检查：所选消息范围、单回答标题、分块在浏览器内部消息之前发生、Unicode、哈希与完成确认。Native API 使用模拟实现。
- 打包后的真实可执行文件：Native Host 消息帧、本机 Socket 转发和未配对来源拒绝。Socket 对端为测试夹具，没有启动客户端 UI。
- Chromium UI 夹具：实际阅读界面、原貌样式与图表比例、脚本/外部资源阻断、目录、中文搜索、星标、收藏夹/标签/备注、已读、回收站恢复。原生命令接口模拟。
- 独立 WKWebView/CoreGraphics：120 行代码跨三页完整保留；彩色长图在第二页完整输出；页面有可提取文字，没有整页空白，也没有跨页重复末尾代码。
- 已有扩展规则与 UI 回归通过，旧服务导出路径保留。

## 0.1.1 / 扩展 1.2.2：网页 PDF 通道

修正了网页 PDF 按钮仍只请求旧 HTTP 后端的问题。弹窗增加客户端/服务选择，默认客户端；客户端接收持久化导出任务、选择保存路径并生成文件，网页轮询 Native Messaging 状态。成功、取消、失败分别返回，不会在仅收到内容时就报告导出成功。旧服务无法连接时显示地址及具体处理方式。

新增 Rust 队列持久化、幂等、取消和中断恢复检查；网页 UI 验证客户端模式不请求 HTTP 后端；客户端 UI 夹具验证真实保存逻辑调用与取消/失败状态传播（原生接口模拟）。安装后的跨浏览器完整点击流程仍待验收。

## 扩展 1.2.3：捕获后的资源整理

修正“捕获 1/1”之后仍扫描全站字体、进度不变的问题。字体仅按所选 DOM 使用的 font-family 收集；字体与背景最终整理阶段总预算20秒，请求、后台回退和响应正文读取均有时限；资源失败保留警告并继续。新增永不返回请求、响应正文挂起、排队资源、未使用字体过滤和成功字体内嵌的回归检查。无需更新客户端。

## 扩展1.2.4：旧网页脚本恢复

修正扩展重载后旧脚本继续留在网页、偏好读写直接抛出 context invalidated 的问题。增加 bootstrap、页面健康检查、安装/重载/启动和标签页加载后的重新注入；新旧 UI 交接保留消息选择，支持旧版没有 dispose 的隐藏退役方案。工具栏“选择消息”也复用修复通道。导出自行调用客户端握手，无需设置页预热。

已通过背景事件/并发重注入/冷客户端握手模拟回归，以及真实 Chromium 中不刷新网页替换 UI、保留选择与旧版 UI 退役测试。原生界面工具仍拒绝访问拾页，没有退出用户正在使用的客户端进行真实冷启动实测。

事件依据：[Chrome runtime onInstalled](https://developer.chrome.com/docs/extensions/reference/api/runtime/#event-onInstalled)（未打包扩展重载被视为更新）。

## 0.2.0 / 扩展 1.3.0：客户端高级 PDF

客户端仅使用网页原貌引擎，不集成 Pandoc。网页与内容库导出支持纸张/方向/边距、字体与字号、暗色、内容标题、独立目录书签和目录页、内部链接、页码、按提问分页、来源链接与消息元信息。原生任务持久保存这些选项，并通过能力版本拒绝旧客户端静默忽略设置。旧数据库自动补充任务选项列。

通过独立 WKWebView 区域捕获与 PDFKit 合成检查书签/目录页的四种组合、跳转目标、纸张尺寸、代码全文和页码。界面与扩展传输检查使用模拟原生命令；安装后的完整操作流程仍需人工验收。

## 0.2.1：代码栏黑条

在实际收藏快照与用户已导出 PDF 中复现代码语言栏变黑。共用分页处理将代码表面相同颜色的半透明渐变预合成为实色，保留语言标签和代码高亮，不改图表的真实渐变。已用实际快照通过 WKWebView 重新生成并检查；浅色/暗色回归、120 行代码完整性、整图分页以及服务端分页检查通过。旧收藏重新导出即可生效，不需要重新捕获。
